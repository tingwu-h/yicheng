## 项目介绍

**驿程**是一款面向西安及周边游客的旅行规划与陪伴平台。我们把景点资料、地图、行程安排与同行协作放在同一条使用路径中：先找到想去的地方，再把它们整理成每天的计划，最后邀请伙伴一起游玩，留下这次旅行的记录。

产品融入新中式唐风与秦岭四宝萌宠。用户可以通过可选任务获得成长和装扮反馈，也可以跳过任务、关闭提醒，按自己的节奏旅行。

当前版本收录 **24 个景点**，提供 **4 只秦岭四宝萌宠**与 **106 件分层服饰**，覆盖景点发现、行程规划、任务探索和小队同行等核心场景。

## 一次旅行，怎样使用驿程

1. **出发前找到想去的地方**：按区域、景点类型与适游主题筛选，查看景点资料、交通提示与地图分布。
2. **把收藏变成每日安排**：将景点加入行程，调整日期、顺序、时间和备注，保存自己的游玩方案。
3. **邀请朋友一起游玩**：通过邀请码加入同行小队，共享同一次游玩的任务进度。
4. **按兴趣探索并留下记录**：选择景点任务，让萌宠陪伴成长；结束游玩后回看行程与同行记录。

## 核心功能

| 功能 | 可以做什么 |
| --- | --- |
| 景点发现 | 浏览西安及周边景点，按区域、类型和主题筛选，查看实景图与实用资料 |
| 地图与 3D 景点 | 查看真实坐标与地点分布，部分景点支持旋转、缩放的 3D 模型 |
| 行程规划 | 按天添加景点，调整游玩顺序、时间和备注，保存方案并查看顺路提示 |
| 同行小队 | 通过邀请码组队，共享任务进度，保存成员与游玩记录 |
| 任务探索 | 参与系统任务、创建自己的任务，自愿提交审核后供其他账号参与 |
| 萌宠与装扮 | 解锁秦岭四宝，完成任务积累成长，使用金币搭配服饰与外观 |
| 手札与交流 | 收录网页探索发现，浏览社区示例内容，体验本地草稿与记录功能 |

地图连线表示游玩顺序，里程提示使用直线距离。景点票价、开放时间与预约信息请在出行前核实。

## 项目特色

### 景点资料与旅行安排相连

景点详情可以直接接入行程。保存后的方案能够继续用于游玩与小队协作，让“想去哪里”自然接上“哪天去、和谁去”。

### 带着秦岭四宝探索长安

棕色大熊猫七仔、朱鹮、川金丝猴与羚牛各有性格与互动风格。成长、服饰和景点探索结合，为旅行提供可感知的陪伴反馈。

### 任务可做可不做

任务提供“稍后提醒、今天不再提醒、不感兴趣、跳过”等选择。跳过不扣金币、不降权；关闭提醒后，清单、金币与已有萌宠仍保留。

金币仅用于产品内的虚拟奖励与装扮，**不可充值、不可提现、不可兑换现金**。小队共享进度，金币只结算给实际完成者。

### 新中式唐风界面

朱砂红、宣纸米白与浅金色构成主要视觉，搭配牌楼 Logo、景点画卷和唐风虚拟形象，让界面与西安旅行主题保持一致。

## 当前进展

已接入真实账号会话，以及按账号保存的资料、收藏、行程、任务奖励、萌宠服饰、小队和游玩记录。公开自建任务支持管理员审核，奖励由服务端校验和结算。

项目已提供 Ubuntu 虚拟机运行方式，通过 Nginx 提供局域网访问，并可按需启用隧道分享临时 HTTPS 地址。当前以原型展示和试用为主，尚未迁移至独立云服务器；访问依赖运行设备、网络与隧道状态。

继续完善的部分包括：

- 多人联网社区与云端手札。社区试发、草稿、网页探索记录和本地通知仍主要保存在当前设备。
- 邮箱验证、找回密码、照片内容审核与任务照片上传界面。
- 移动端定位、扫码校验、防刷和多设备体验验收。

社区预设内容属于演示资料，手札中的网页探索记录不代表实际到访。

## 本地运行

需要 **Node.js 24 或更新版本**。

```bash
git clone https://github.com/tingwu-h/yicheng.git
cd yicheng
npm ci
npm run start:local
```

Windows 用户也可以双击根目录的 **一键启动.cmd**。快捷启动会检查依赖和服务，已有服务可复用；详细说明见 [快捷启动说明](快捷启动说明.md)。

默认网页地址：[http://127.0.0.1:5180/](http://127.0.0.1:5180/)。在线模式需要注册账号并使用真实密码登录。

<details>
<summary><strong>手动启动、检查与部署</strong></summary>

分别在两个终端运行：

```bash
# 终端一：后端
npm run dev:api

# 终端二：网页
npm run dev -- --host 127.0.0.1
```

后端默认监听 `127.0.0.1:5181`，网页通过同源 `/api` 代理访问。修改后端代码后需要重启后端。

```bash
npm test             # 业务逻辑检查
npm run test:api      # 后端接口检查
npm run test:render   # 页面渲染检查
npm run build        # 生产构建
npm run backup:api   # 数据库备份
```

生产构建输出到 `dist/`，部署时需要静态服务器和 `/api` 同源反向代理。仅部署静态文件无法提供账号保存、小队协作和服务端奖励结算。

仓库包含应用源码、静态图片与模型、依赖锁文件及文档。`src/data/` 是需要提交的静态应用配置；根目录 `/data/` 是私有运行数据库目录。数据库、上传文件、环境密钥与备份不提交到仓库。

Ubuntu 桌面上的公网开关和二维码工具属于现有虚拟机的运维配置，克隆仓库不会自动安装。设备休眠、虚拟机关机或断网会中断访问；重启隧道后临时地址可能变化。

管理员入口为 `/#/admin`，没有默认管理员密码。账号权限、备份、接口与部署配置见 [后端搭建说明](docs/后端搭建说明.md)。

</details>
