# 驿程-vh-0.7 · 西安旅游信息与交流平台

## 双击快捷启动

完整解压后，双击根目录的 **一键启动.cmd**。它会检查依赖、启动网页和后端、检查连接并打开浏览器；已有服务会复用，端口冲突不会强制关闭其他程序。需要 Node.js 24 或更新版本。详见 [快捷启动说明](快捷启动说明.md)。命令行也可运行 npm run start:local。

## 后端第一阶段（2026-10-02）

现有前端已接入 Node.js 24 + SQLite 后端。账号、资料、头像、收藏、行程、任务、金币、萌宠、服饰、真实小队和游玩记录按账号保存。旧本机演示数据不删除，也不自动导入线上账号。

完整接口、迁移、权限、备份及限制见 [后端搭建说明](docs/后端搭建说明.md)。管理员入口为 /#/admin，没有默认管理员密码。

### 启动

首次解压安装依赖：npm ci。随后在项目目录开两个终端：

    npm run dev:api

    npm run dev -- --host 127.0.0.1

网页 http://127.0.0.1:5180/ ，后端默认只监听 127.0.0.1:5181，网页通过同源代理访问。在线模式需要注册后凭真实密码登录。后端代码修改后要重启后端；结束开发运行可在两个终端按 Ctrl+C。不要因端口占用直接结束不明进程。

### 验证和维护

    npm test
    npm run test:api
    npm run test:render
    npm run build
    npm run backup:api

备份位于 data/backups，包含私人账号数据，不放入分发 ZIP。生产构建为 dist，需要静态服务器及 /api 同源反向代理；不能双击 HTML 或仅部署静态页面就当后端完成。

## 虚拟形象

`src/components/Avatar.jsx` 用分层 SVG 程序化生成，无需任何图片资源：
8 种冠饰 × 6 种甲胄 × 5 种面容 × 4 套配色，内置 30 款预设（骠骑、定远……），
注册时可选，之后在个人中心自由搭配冠饰、甲胄、面容与配色。

## 任务提醒 · 金币 · 萌宠

在「发现 → 了解 → 规划 → 记录」之外，新增一条**可选**的辅助线：
把想玩 / 想拍 / 想体验的先记下来，到了合适的时间由萌宠轻声提一句。

- **预录项目**：景点详情页可把「想玩 / 想拍 / 想体验 / 想吃」记进清单。
  项目来源有两处——景点自带的结构化 POI（已试点 5 个景点），
  以及从景点亮点自动派生的建议，保证每个景点都有可选项目。
- **任务化提醒**：引擎按时间、位置、天气、排队、在园时长在合适的时机下发**一张**任务卡，
  含标题、说明、步骤、完成条件、奖励金币与安全提示。
- **金币**：只能通过完成任务获得。**不可充值、不可提现、不可兑换现金**——
  流水表的来源枚举里就没有这三项，是结构上的约束，不是文案声明。
- **萌宠**：以秦岭四宝为原型（棕色大熊猫七仔 / 朱鹮 / 川金丝猴 / 羚牛），
  各有性格与话术风格；金币可解锁萌宠、购买唐装与兵马俑盔甲等装扮。
  形象与虚拟形象一样用**程序化 SVG** 分层绘制，不含任何图片资源。

### 非强迫原则（写进了代码结构）

- 任务卡的四个出口一屏可见：**稍后提醒 / 今天不再提醒 / 不感兴趣 / 跳过**。
- 跳过与关闭**不扣金币、不降权、不记录失败**——金币流水里不存在负数惩罚项，
  也不存在 `task_failed` 这类埋点。
- 「不感兴趣」会记进偏好并**可随时撤销**；同一模板出现次数达上限后自动静音。
- 默认克制：每天最多 2 次、间隔至少 45 分钟、22:00–08:00 不打扰。
- 一键全关：关闭提醒后清单、金币与萌宠都还在，不会因为关闭而损失任何东西。
- 文案过词表：任务卡与话术里不出现「还剩 / 已错过 / 限时 / 赶紧」这类催促词。

### 演示环境的如实说明

本项目没有后端，因此：

- 位置、天气、排队由行前清单页的**场景模拟器**给出，界面与数据里都标注为模拟，
  不读取真实定位；
- 需要位置或扫码校验的任务，演示版允许手动确认，并在记录里标记已降级；
- 提醒渠道只有**站内消息 + 应用内任务卡**，小程序订阅消息与 App 推送在当前项目
  没有载体，只保留了配置位与接口契约（见 `docs/quest/API.md`）；
- 数据存在 localStorage 的 `changan-banlv-quest-v1`，与既有的
  `changan-banlv-state-v1` 分离，互不影响。

### 想接后端时

接口契约、数据模型、埋点与建表脚本都已备好：

- `docs/quest/API.md` —— 统一返回格式 `{ code, message, data }`、错误码、请求/响应示例、
  切换步骤
- `docs/quest/SCHEMA.md` —— 9 个集合 / 表的字段说明与版本迁移规则
- `docs/quest/migrations/001_quest.sql` —— 只新增表的建表脚本，不改任何既有表
- `docs/quest/EVENTS.md` —— 埋点清单与建议盯的四个指标
- `docs/quest/ACCEPTANCE.md` —— 验收清单、回归测试建议与已知限制

开关与配置集中在 `src/data/questConfig.js`（模板、奖励、频率、安静时段、话术、词表），
改数值不需要动业务代码。

## 交互约定

- 列表页均具备 **加载中 / 空结果 / 加载失败 + 重试** 四态；景点库加 `?demo=error` 可查看失败态。
- 所有筛选条件可见，并提供**一键清除**与已选条件标签。
- 收藏、点赞、评论、发布、加入行程均有即时 Toast 反馈。
- 涉及票价、开放时间、交通的信息标注更新时间与「出行前请核实」，并声明用户内容不代表官方。
- 未登录可浏览全部内容，触发收藏/发布等操作时弹登录框并说明登录后可获得的能力。
- 地图为真实底图，可拖拽平移、滚轮缩放、双击放大，支持键盘方向键与 `+/-/0`。
- 地图里程均为**直线距离**，不提供实时路况与导航测距。
- 顶栏在 ≤900px 收起为抽屉；≤480px 压缩间距与按钮内边距，≤400px 隐藏品牌副标题，避免横向滚动。
- 任务提醒是可选的加分项：不做任何任务也不会扣金币、不会被降权、不会被反复催促；
  顶栏的金币入口刻意做小，不抢「景点 / 行程 / 社区」的主路径。
- 涉及体力的任务都带安全提示（拍照留意脚下、雨天路滑、带孩子约定集合点等）。
