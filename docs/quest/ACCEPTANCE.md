## 三、回归测试建议（重点看「有没有弄坏老东西」）

1. **老数据兼容**：先用改动前的版本在浏览器里操作一遍（收藏几个景点、建一份行程、
   存一条草稿），再切到新版本刷新——
   - 收藏、行程、草稿、浏览记录、消息**全部还在**；
   - localStorage 里应同时存在 `changan-banlv-state-v1` 与 `changan-banlv-quest-v1` 两个键。
2. **消息中心**：原有评论/点赞/收藏/系统四类通知仍在；新任务提醒归入「任务提醒」分类；
   点任一条仍能正确跳转（旧通知跳帖子，任务提醒跳行前清单）。
3. **顶栏**：新增的金币入口在 1200 / 900 / 720 / 375 四个宽度下都不挤掉导航与搜索；
   极窄屏只留金币数字。
4. **导航与路由**：`/quests`、`/pets` 直接粘贴到地址栏可打开；
   浏览器的前进/后退正常；刷新后仍停在当前 tab（`?tab=`）。
5. **景点详情页**：新增的「想玩的项目」区块在移动端不遮挡「收藏 / 加入行程 / 分享」。
6. **行程页**：新增的行前清单卡片只读展示，不改变拖拽排序、备注、时间、删除等既有逻辑。
7. **个人中心**：侧栏新增 3 个 tab 后，原有 8 个 tab 的计数与内容不受影响；
   直接访问 `/profile?tab=coins` 能落到正确 tab。
8. **构建产物**：`npm run build` 后双击 `dist/index.html`（不开服务器）——
   路由跳转、任务卡、萌宠页都要正常。
9. **隐私模式**：浏览器无痕模式下写入 localStorage 失败时，界面不崩、不白屏。
10. **StrictMode 双调用**：开发模式下 React 会双调用 effect，
    验证不会出现「两张任务卡」或「金币发两次」。

## 四、边界与异常用例

| 场景 | 期望 |
| --- | --- |
| 清单里的景点被删除（数据不存在） | 行前清单显示「未知景点」，不报错 |
| 任务卡对应的记录已被清理 | 点完成提示「这张任务卡已经过期了」 |
| 本地数据被手工改坏（字符串 / 缺字段） | 退回默认值，界面可用 |
| 跨零点使用（23:50 提醒，00:10 完成） | 归属日期按本地日期计算，不出现重复发币 |
| 小程序订阅消息 / App 推送 | 当前项目**没有载体**，只有配置位与契约，界面不出现相关开关 |
| 定位权限被拒 | 演示环境为模拟位置，不影响任何功能；文案已声明不读取真实定位 |

## 五、已知限制（写清楚，避免被当成缺陷）

1. **无真实后端**：数据在 localStorage，换浏览器或清缓存即丢失；
   多设备同步、服务端校验、真实防刷都要等后端。
2. **场景为模拟**：位置、天气、排队三项由场景模拟器给出，
   界面与文档均如实标注「模拟」，不暗示真实定位。
3. **推送未接入**：站内消息 + 应用内任务卡是当前仅有的两个渠道。
4. **位置/扫码校验降级**：模板要求位置或扫码时，演示版允许手动确认，
   并在记录里标 `verifyDowngraded`，界面注明。
5. **自动调度粒度**：前端每分钟检查一次，且只在页面可见时进行；
   离开页面不会有提醒（没有推送能力）。
