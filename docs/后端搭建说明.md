## 2. 本机启动与停止

从交付包解压后先安装 Node.js 24.x 并运行 npm ci。当前项目已有依赖时不需重新安装。打开两个项目终端：

终端一：

    cd C:/codex/驿程-vh-0.7
    npm run dev:api

终端二：

    cd C:/codex/驿程-vh-0.7
    npm run dev -- --host 127.0.0.1

网页地址为 http://127.0.0.1:5180/ 。API 默认只监听 127.0.0.1:5181，网页通过 Vite 的 /api 代理访问。修改服务端文件需重启后端；端口占用时先确认是否已有服务运行，不随便结束其他程序。结束本次运行，在对应终端按 Ctrl+C。

默认在线模式需要真实注册，不再接受任意密码或前端“全解锁”标记。没有预设管理员或默认密码。邮箱暂未验证，不要使用重要账号的常用密码，不要填写敏感资料。

### 管理员

先在网页注册自己的账号，再由项目/服务器管理者执行：

    npm run admin:grant -- 你已经注册的邮箱

重新登录后访问 /#/admin。普通网页请求无法自封管理员；共享展示电脑不要保留管理员登录。

### 配置

参考根目录 .env.example；本机可直接使用默认值，按需创建 .env。不要提交 .env 或密码到交付包。

| 变量 | 默认值或要求 |
|---|---|
| API_HOST | 127.0.0.1，保持内网监听 |
| API_PORT | 5181，改变后同步调整 Vite 或服务器反向代理 |
| DATABASE_PATH | 默认项目 data/backend.sqlite，可设独立持久化文件 |
| PUBLIC_ORIGIN | 本地为 http://127.0.0.1:5180,http://localhost:5180；生产精确填写 HTTPS 网站源 |
| NODE_ENV | 生产使用 production，会要求 HTTPS 并设置 Secure Cookie |
| TRUST_PROXY | 仅本机可信反向代理覆盖 X-Real-IP 时设为 1 |
| VITE_APP_MODE | server 为默认；demo 显式恢复旧本机演示，不能用于线上安全结算 |
| TZ | Asia/Shanghai，任务日期由服务端确定 |

旧 localStorage、旧配置服务及旧数据库均未删除，不自动导入到线上账号。浏览器中的金币、宠物库存不可信，不能直接导入作为真实奖励。旧配置服务文件保留，但不要与新后端同时启动。

## 3. 数据库与迁移

启动时自动执行 server/migrations 下的 001_backend.sql、002_public_tasks.sql，各执行一次，由 schema_migrations 记录。新增独立数据库，不改旧演示数据。

| 表/存储 | 用途 |
|---|---|
| users / sessions | 用户、密码散列、会话令牌散列与失效时间 |
| user_documents | 按账号保存资料/行程/任务/宠物/服饰文档和修订号；提前退出记录也在此隔离存储 |
| coin_ledger | 独立金币流水，用户+流水编号和用户+幂等键均唯一 |
| task_submissions | 私有、待审核、通过、退回、已删除任务 |
| public_task_completions | 用户+公开任务唯一完成记录，完成量不接受前端自报 |
| official_config / audit_log | 官方配置和管理审计 |
| journeys / journey_members | 小队、游玩、共享进度与成员关系 |
| media | 用户私有图片，仅本人可访问和删除 |

兼容方式是把现有业务规则放到服务端执行，保留前端状态结构。宠物/服饰定义仍来自项目配置；库存和进度按用户保存；金币另有事务流水校验。不是把前端数组原样信任上传。

## 4. 关键接口与示例

保护接口需要登录 Cookie。修改请求需要同源 Origin 及 X-Yicheng-Request: 1；JSON 请求使用 Content-Type: application/json。浏览器适配器在 src/services/backendClient.js。切勿将密码、Cookie 或数据库写进前端 bundle。

| 方法/接口 | 用途 |
|---|---|
| GET /api/health | 健康状态 |
| POST /api/auth/register、/login、/logout | 注册、登录、退出 |
| GET /api/auth/me | 当前账号 |
| GET、PUT /api/me/app | 资料、收藏、行程；PUT 必须提供 revision |
| GET /api/me/quest、/api/me/coins | 任务库存、余额及最近 200 条流水 |
| POST /api/quest/actions/:action | 白名单任务、提醒、穿戴、购买、升级动作 |
| GET /api/tasks/public | 最近 200 项已审核公开任务 |
| POST /api/tasks/public/complete | 完成公开任务并更新作者完成量 |
| GET /api/journeys | 当前游玩与最近 100 条记录 |
| POST /api/journeys/start、/join、/finish | 开始、加入、结束整队或退出本人 |
| POST /api/media | 图片二进制上传：JPEG/PNG/WebP，单张不超过 2MB，账号不超过 20MB |
| GET、DELETE /api/media/:id | 仅本人读取、删除图片 |
| GET /api/admin/overview、/api/admin/users/:id | 管理概览、进度和流水 |
| PUT /api/admin/config/:key | coreChains / activityTasks / officialTaskConfig |
| POST /api/admin/review | 公开任务审核 |

注册请求（示例，不是内置账号）：

    {"account":"visitor@example.test","password":"ExampleOnly123!","name":"小旅人","agree":true}

成功响应不含密码或明文会话令牌；会话通过 HttpOnly Cookie 保存：

    {"user":{"id":"user-…","email":"visitor@example.test","name":"小旅人","role":"user","isInternalTest":false}}

保存资料：GET /api/me/app 得到 data 和 revision，修改 data 后 PUT 整份文档 {revision,data}。返回新 revision。409 时保留当前编辑内容，刷新核对后重试，不强制覆盖。

创建任务，POST /api/quest/actions/createCustomTask：

    {"attractionId":"a1","title":"拍一张喜欢的屋檐","type":"photo"}

成功返回 {code:0,message,data:{id:任务ID,…},state:新的任务状态}。完成时 POST /api/quest/actions/completeCustomTask：

    {"taskId":"服务端创建的任务ID","evidence":{"photoSelected":true,"publish":false}}

photoSelected 目前是自愿确认，不代表照片已上传或真实性已审核。金币由服务器决定；提交 coins、userPets 等字段会被拒绝。重复完成不重复奖励。公开任务完成接口为 /api/tasks/public/complete，相同 taskId/evidence 结构。

开始游玩：POST /api/journeys/start，正文 {"tripId":"已保存的行程ID"}；响应 {active:{id,trip,ownerId,members,inviteCode,…}}。加入：{"code":"12位邀请码"}；结束/退出：{"sessionId":"当前会话ID"}。队员退出不结束其他人；发起人结束全队。

审核：POST /api/admin/review，正文 {"taskId":"…","approved":false,"reason":"请把标题写得更具体"}。普通用户返回 403，重复审核返回 409；审核不重复发金币。

前端调用示例：

    import { apiRequest } from './services/backendClient'
    async function startSavedTrip(tripId) {
      const { active } = await apiRequest('/api/journeys/start', {
        method: 'POST', body: { tripId },
      })
      return active
    }

调用失败应显示提示并允许重试，不能自动降级到本机发奖。实际页面联动见 AppContext、QuestContext、JourneyContext、TaskCenter、Admin、PlayTrip。

## 5. 备份与交付

    npm run backup:api

脚本使用 SQLite 一致性快照，并执行完整性检查，保存到 data/backups。不能只复制正在运行的 backend.sqlite 而遗漏 WAL 的新数据。备份含用户数据，需单独妥善保管，不进入公开压缩包。

恢复：停止后端，保留现有数据库及 WAL/SHM 的离线副本；把经过检查的备份复制为一个新文件，将 DATABASE_PATH 指向新文件，再启动检查。不要覆盖正在运行的数据库。

交付包排除 node_modules、数据库、备份、.env、日志和测试临时文件；保留 .env.example、源码、迁移脚本、测试和生产 dist。不要把本机测试账号数据库上传到正式服务器。
